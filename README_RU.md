# Cairn — руководство на русском

[English version — README.md](README.md)

Полное руководство по установке и использованию Cairn на русском языке.
Это не построчный перевод английского README, а отдельное практическое
руководство — все команды, названия инструментов и переменные окружения
взяты из исходников репозитория (`docs/INSTALL.md`, `docs/TOOLS.md`,
`package.json`).

## Что это

Cairn — это локальная, портируемая память для MCP-клиентов (Claude Desktop,
Claude Code, Cursor и других). Вся память хранится в одном файле на вашей
машине, а не в облаке; один и тот же файл видят все подключённые клиенты, так
что то, что вы рассказали в одном приложении, можно спросить в другом.
Запись памяти никогда не вызывает LLM — только локальное встраивание
(embedding). Проект распространяется под лицензией MIT.

## Установка

Требуется Node.js ≥22. Основной путь — запуск прямо из npm, без отдельной
установки:

```bash
npx cairn-mem
```

Это запускает stdio-shim, который используют MCP-клиенты; в терминале без
клиента команда просто печатает статус. Можно также поставить пакет
глобально, чтобы команда `cairn` была всегда доступна в `PATH`:

```bash
npm install -g cairn-mem
```

Из исходников (для разработки):

```bash
git clone https://github.com/Evelynkaz/cairn.git
cd cairn
npm install
npm run build
node dist/cli/index.js
```

## Быстрый старт

1. **Подключите MCP-клиентов.** `npx cairn-mem setup` правит реальные файлы
   конфигурации на вашей машине (конфиг Claude Desktop, `~/.claude.json` для
   Claude Code, `~/.cursor/mcp.json` для Cursor). Перед тем как запускать
   по-настоящему, посмотрите, что именно будет изменено:

   ```bash
   npx cairn-mem setup --dry-run --print   # показывает, что будет записано, ничего не пишет
   npx cairn-mem setup                     # пишет по-настоящему
   ```

   Для Claude Code есть более безопасная альтернатива, поскольку сам
   Claude Code постоянно пишет в `~/.claude.json`, пока работает:

   ```bash
   claude mcp add cairn -- npx -y cairn-mem@latest
   ```

2. **Перезапустите клиента.** Демон (фоновый процесс, который хранит базу)
   в этот момент ещё не запущен — stdio-shim запускает его автоматически при
   первом реальном обращении клиента.

3. **Как это работает на практике.** Модель сама решает, когда вызвать
   `remember` (сохранить) или `recall` (вспомнить) — вам не нужно вызывать
   инструменты вручную. Пример: скажите Claude «запомни, что для новых
   проектов я предпочитаю TypeScript вместо JavaScript», а затем в новом
   разговоре в Cursor спросите «какой язык я предпочитаю для новых
   проектов?» — Cursor получит ответ, потому что оба клиента используют один
   и тот же демон и один и тот же файл SQLite.

## Команды CLI

| Команда | Что делает |
|---|---|
| `npx cairn-mem` | запускает stdio-shim при вызове из клиента; в терминале печатает статус |
| `npx cairn-mem status [--json]` | показывает состояние демона, эмбеддингов и базы данных |
| `npx cairn-mem start` | запускает демон в фоне |
| `npx cairn-mem stop` | останавливает демон |
| `npx cairn-mem ui [--no-open]` | запускает демон (если не запущен) и печатает/открывает адрес дашборда |
| `npx cairn-mem setup [--client=<id>...] [--dry-run] [--print]` | подключает Claude Desktop / Claude Code / Cursor |
| `npx cairn-mem mcp` | всегда запускает stdio-shim |
| `npx cairn-mem embeddings status\|enable [--provider=<name>] [--model=<id>]\|disable` | управляет режимом эмбеддингов |
| `npx cairn-mem hook session-start` | печатает конверт для хука `SessionStart` в Claude Code |
| `npx cairn-mem --version` / `--help` | версия / справка |

## Дашборд

`npx cairn-mem ui` открывает дашборд, который отдаёт демон. В нём можно:

- просматривать и искать память;
- редактировать записи «на месте»;
- удалять память (с окном отмены);
- одобрять импортированные памяти, прежде чем они станут доступны для
  автоматического подхвата (см. раздел ниже про происхождение памяти);
- смотреть таймлайн — состояние хранилища на любой момент времени;
- смотреть журнал доступа (access log) и статистику.

## Восемь инструментов MCP

Cairn намеренно ограничивает набор инструментов восемью (см.
`docs/TOOLS.md` — это источник истины):

- **`remember`** — сохранить память. Вызывается, когда пользователь
  сообщает устойчивое предпочтение, решение, факт о себе или исправление —
  что-то, что должно оставаться верным и восстанавливаться в будущих
  разговорах. Никогда не вызывает LLM или сеть.
- **`recall`** — гибридный поиск (FTS5 + вектор, слияние через RRF).
  Вызывается ПЕРЕД ответом на всё, что может зависеть от предыдущего
  контекста — предпочтений, прошлых решений, фактов о проекте.
- **`get_context`** — один блок с бюджетом токенов (~800 по умолчанию) с
  самыми релевантными памятями, готовый к вставке в контекст. Вызывается
  перед ответом на что-то, что может зависеть от прошлого контекста,
  особенно в начале сессии — вместо выгрузки всего хранилища.
- **`list_memories`** — просмотр памяти с постраничной навигацией, для
  аудита, курирования или поиска записи, которую нужно изменить или
  удалить, когда нечёткий поиск через `recall` недостаточно точен.
- **`update_memory`** — редактирование содержимого, тегов или важности уже
  существующей записи. Вызывается, когда пользователь исправляет или
  уточняет что-то уже сохранённое, вместо создания дубликата через
  `remember`.
- **`forget`** — удаление памяти. Вызывается, когда пользователь явно
  просит забыть, удалить или убрать что-то, что он рассказал.
- **`export_memories`** / **`import_memories`** — переносимый экспорт/импорт
  в ZIP-архив, плюс импортёры вставленного текста памяти Claude/ChatGPT и
  экспортированных пользовательских инструкций ChatGPT.

## Приватность

- Секреты и персональные данные редактируются (маскируются) при записи;
  режим управляется переменной `CAIRN_PRIVACY` со значениями `off` / `on`
  (по умолчанию) / `strict` — в режиме `strict` запись, содержащая найденный
  секрет, отклоняется целиком.
- Удаление — полноценная функция первого класса, с окном отмены.
- Никакой телеметрии — нигде в коде.
- Запись памяти (`remember` и все остальные пути записи) никогда не
  обращается к LLM — только локальное встраивание, либо вообще без
  встраивания в режиме только полнотекстового поиска (FTS-only).

## Импорт из Claude/ChatGPT

Импорт доступен через `import_memories` (принимает архив, ранее записанный
`export_memories`) и через отдельные импортёры вставленного текста памяти
Claude/ChatGPT и экспортированных пользовательских инструкций ChatGPT.
**Честно:** эти импортёры от сторонних продуктов ни разу не прогонялись на
реальном экспорте из Claude или ChatGPT. Но импорт сначала показывает разбор
(preview) содержимого до фактической записи в базу, так что неверный разбор
виден заранее и ошибку легко отменить — это не слепая необратимая операция.

## Происхождение памяти и одобрение

Каждая запись памяти хранит поле происхождения (`origin`: `user` / `import`
/ `unknown`) и флаг `approved`. Хук `SessionStart` (см. ниже) автоматически
подставляет в контекст только память, созданную самим пользователем, или ту,
что явно одобрена в дашборде — импортированная и неодобренная память в
автоматическую подстановку не попадает. Это сделано специально: импортированный
текст — это чужой, непроверенный текст, и если бы он подставлялся в контекст
автоматически, это была бы готовая лазейка для промпт-инъекции через чужие
данные. Инструмент `get_context`, вызываемый моделью намеренно, доступ к
непроверенной памяти не блокирует, а лишь помечает её происхождение — модель
может сама решить, доверять ли ей.

## Где хранится база

Один файл: `~/.cairn/cairn.db` (SQLite в режиме WAL), рядом с его
`-wal`/`-shm` файлами и файлом состояния демона — всё внутри `~/.cairn`.
Переопределить домашнюю директорию Cairn целиком можно переменной
`CAIRN_HOME`, например: `CAIRN_HOME=/path/to/dir npx cairn-mem status`.
